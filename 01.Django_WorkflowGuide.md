## 二、架构概览（MVT / 项目结构）

Django 采用 **MVT** 架构，是对传统 MVC 的变体：

```
用户浏览器发起 HTTP 请求（URL）
   ↓ ① URLconf（urls.py）        路由匹配，找到对应视图函数
   ↓ ② View（views.py）          视图函数接收请求，处理业务逻辑
   ↓   ↕ Model（models.py）      视图与 ORM 交互，操作数据库
   ↓ ③ Template（templates/）    视图将数据传入模板，渲染为 HTML
返回 HTTP 响应（HTML / JSON / 重定向）给浏览器
```

### 2.1 MVT 三层职责对比

| 层次              | Django 对应      | MVC 对应     | 职责                          |
| --------------- | -------------- | ---------- | --------------------------- |
| Model（模型）       | `models.py`    | M — Model  | 与数据库交互，定义数据结构               |
| View（视图）        | `views.py`     | C — Controller | 接收请求，处理逻辑，与 M/T 交互，返回响应   |
| Template（模板）    | `templates/`   | V — View   | 生成 HTML 页面，控制展示内容           |

### 2.2 项目目录结构

```
myproject/                    ← 项目根目录（manage.py 所在位置）
├── manage.py                 ← 项目管理脚本，开发期间所有命令的入口
├── db.sqlite3                ← Django 默认 SQLite 数据库文件（迁移后生成）
├── templates/                ← 项目级模板目录（需手动创建）
├── static/                   ← 项目级静态文件目录（需手动创建）
│   ├── css/
│   ├── js/
│   └── images/
├── myproject/                ← 项目配置包（与项目同名）
│   ├── __init__.py           ← 声明该目录为 Python 包
│   ├── settings.py           ← 项目全局配置文件（数据库/应用/中间件等）
│   ├── urls.py               ← 项目级 URL 路由配置（根路由）
│   ├── wsgi.py               ← WSGI 服务器入口（生产部署使用）
│   └── asgi.py               ← ASGI 异步服务器入口（Django 3.0+ 新增）
└── booktest/                 ← 自定义应用目录
    ├── __init__.py           ← 声明该目录为 Python 包
    ├── admin.py              ← 注册模型类到 Admin 后台
    ├── apps.py               ← 应用配置类
    ├── models.py             ← 定义数据模型类（ORM）
    ├── views.py              ← 定义视图函数
    ├── urls.py               ← 应用级 URL 路由（需手动创建）
    ├── tests.py              ← 单元测试 / 数据库脚本文件（可用 python manage.py test 应用名 运行）
    └── migrations/           ← 数据库迁移文件目录（自动生成）
        └── __init__.py
```

### 2.3 核心组件一览

| 组件            | 文件位置                  | 功能                            |
| ------------- | --------------------- | ----------------------------- |
| URL 路由        | `urls.py`             | 将 URL 路径映射到视图函数               |
| 视图函数          | `views.py`            | 接收请求 → 处理逻辑 → 返回响应            |
| 模型类           | `models.py`           | 定义数据表结构，通过 ORM 操作数据库          |
| 模板            | `templates/*.html`    | 使用 DTL 生成动态 HTML              |
| Admin 后台      | `admin.py`            | 注册模型，自动生成数据管理界面               |
| 中间件           | `settings.MIDDLEWARE` | 在请求/响应流中插入公共处理逻辑              |
| 配置文件          | `settings.py`         | 数据库、静态文件、已安装应用等全局配置           |

## 三、模型（Model / ORM / 字段类型）

Django ORM 是 **Object-Relational Mapping** 的缩写：
- **O（Object）**：Python 类和对象
- **R（Relation）**：关系型数据库中的表
- **M（Mapping）**：两者之间的映射关系

ORM 的核心功能：
1. 根据模型类**自动生成**数据库表结构
2. 通过类和对象操作数据库，**无需手写 SQL**
3. 支持多种数据库**无缝切换**（SQLite / MySQL / PostgreSQL）

> **字段类型速查表**
>
> | 字段类型                                        | Python 类型    | 说明                                   |
> | ------------------------------------------- | ------------ | ------------------------------------ |
> | `AutoField`                                 | `int`        | 32 位自动增长整数；Django 3.2+ 默认自动生成的 `id` 列类型已改为 `BigAutoField`（64 位），通常不手动指定 |
> | `CharField(max_length=N)`                   | `str`        | 定长字符串，`max_length` 必填               |
> | `TextField`                                 | `str`        | 大文本，超过 4000 字符时使用                   |
> | `IntegerField`                              | `int`        | 普通整数                                 |
> | `BigIntegerField`                           | `int`        | 大整数（-2^63 ~ 2^63-1）                 |
> | `DecimalField(max_digits, decimal_places)`  | `Decimal`    | 高精度小数（金融/价格推荐使用）                    |
> | `FloatField`                                | `float`      | 浮点数（精度较低，不推荐金融场景）                   |
> | `BooleanField`                              | `bool`       | 布尔值 `True` / `False`；允许空值请用 `BooleanField(null=True)`（`NullBooleanField` 已在 Django 4.0 废弃、5.0 中移除） |
> | `DateField`                                 | `date`       | 日期（年-月-日）                            |
> | `TimeField`                                 | `time`       | 时间（时:分:秒）                            |
> | `DateTimeField`                             | `datetime`   | 日期+时间                                |
> | `EmailField`                                | `str`        | 邮箱字段，带格式校验                           |
> | `ImageField(upload_to='路径')`               | `str`（路径）    | 图片字段，数据库存储路径字符串，需安装 Pillow          |
> | `FileField(upload_to='路径')`                | `str`（路径）    | 文件字段                                 |
> | `ForeignKey('ModelName', on_delete=...)`    | 关联模型对象       | 外键，一对多关系，定义在"多"端                    |
> | `ManyToManyField('ModelName')`              | `QuerySet`   | 多对多关系，Django 自动创建中间表                 |
> | `OneToOneField('ModelName', on_delete=...)` | 关联模型对象       | 一对一关系                                |

> **字段公共选项**
>
> | 选项名           | 说明                                         |
> | ------------- | ------------------------------------------ |
> | `default`     | 字段默认值（Django 层生效，非数据库 DEFAULT 约束）         |
> | `primary_key` | `True` 时该字段成为主键，Django 不再自动创建 `id` 列      |
> | `unique`      | `True` 时该字段在表中值唯一                          |
> | `db_index`    | `True` 时为该字段创建数据库索引，加速查询                  |
> | `db_column`   | 自定义数据库列名（不指定时使用属性名）                       |
> | `null`        | `True` 时数据库列允许 `NULL`（默认 `False`）          |
> | `blank`       | `True` 时 Admin 表单允许提交空值（默认 `False`）        |
> | `verbose_name`| Admin 后台显示的字段中文名                           |
> | `db_constraint`| `False` 时不在数据库层面创建外键约束（外键关系仅在 Django 层维护）|

### 3.1 定义模型类

```python
# ============================================================
# booktest/models.py — 定义图书和英雄两个模型类
# 每个模型类对应数据库中的一张表
# 模型类必须继承 django.db.models.Model
# ============================================================

from django.db import models  # 导入 Django ORM 模型基类及字段类型


# ── 一类（图书表，一对多中的"一"端）─────────────────────────────────────
class BookInfo(models.Model):
    """图书模型类，对应数据库表 booktest_bookinfo"""

    # CharField(max_length) -> str
    # 字符串字段，max_length 必填，指定最大字符数
    # db_column: str — 自定义数据库列名（不指定时默认使用属性名）
    btitle = models.CharField(
        max_length=20,          # int: 字段最大字符个数，必填参数
        db_column='title',      # str: 数据库中实际列名（可选，默认为属性名 btitle）
        verbose_name='图书名称', # str: 在 Admin 后台显示的字段中文名称
    )

    # DateField -> date 对象
    # auto_now=True     : 每次 save() 时自动更新为当前日期（用于"最后修改时间"）
    # auto_now_add=True : 首次创建时自动设置为当前日期（用于"创建时间"）
    # 注意：auto_now 与 auto_now_add 互斥，不可同时设为 True
    bpub_date = models.DateField(verbose_name='发布日期')  # date 对象：图书发布日期

    # IntegerField -> int
    # default: 当创建对象不显式赋值时使用的默认值
    # 注意：default 仅在 Django 层生效，不在数据库层面添加 DEFAULT 约束
    bread = models.IntegerField(default=0, verbose_name='阅读量')   # int: 图书阅读量，默认0
    bcomment = models.IntegerField(default=0, verbose_name='评论量') # int: 图书评论量，默认0

    # BooleanField -> bool
    # 用于软删除标记：删除时不物理删除，仅将此字段设为 True，防止重要数据丢失
    is_delete = models.BooleanField(default=False, verbose_name='删除标记')  # bool: 是否软删除

    def __str__(self):
        # __str__ 控制对象转为字符串时的显示内容
        # 影响：Admin 后台列表页、shell 中 print(对象) 的输出
        return self.btitle  # str: 返回图书名称作为对象的字符串表示

    class Meta:
        # Meta 内部类用于定义模型的元数据
        db_table = 'bookinfo'           # str: 自定义数据库表名（默认为 booktest_bookinfo）
        verbose_name = '图书'           # str: Admin 后台中单数显示名称
        verbose_name_plural = '图书列表' # str: Admin 后台中复数显示名称


# ── 多类（人物表，一对多中的"多"端）─────────────────────────────────────
class CharacterInfo(models.Model):
    """人物模型类，对应数据库表 booktest_characterinfo"""

    hname = models.CharField(max_length=20, verbose_name='人物姓名')  # str: 英雄名称

    # BooleanField -> bool
    # default=False 表示默认为女性（False），True 表示男性
    hgender = models.BooleanField(default=False, verbose_name='性别')  # bool: 性别

    # null=True  : 数据库层面允许该字段为 NULL
    # blank=True : 表单验证层面允许该字段为空（Admin 后台提交表单时有效）
    # 经验：null 控制数据库，blank 控制 Admin 表单验证，通常同时设置
    hcomment = models.CharField(
        max_length=200,
        null=True,          # bool: 数据库允许 NULL 值
        blank=True,         # bool: Admin 表单允许提交空值
        verbose_name='人物描述',
    )

    # ForeignKey — 定义外键（一对多关系），必须定义在"多"的一端
    # 第一个参数: 关联的模型类名（字符串形式，避免因类定义顺序导致的 NameError）
    # on_delete  : 当被关联记录删除时的处理策略
    #   CASCADE   — 级联删除（删除图书时，关联的人物也全部删除）
    #   SET_NULL  — 设为 NULL（需同时设置 null=True）
    #   PROTECT   — 阻止删除（有关联数据时抛出异常）
    #   SET_DEFAULT — 设为 default 参数指定的默认值
    # related_name : 反向查询名，一类通过此名查询多类（默认为 <多类名小写>_set）
    hbook = models.ForeignKey(
        'BookInfo',                 # str: 关联的模型类名（字符串写法，避免因类定义顺序导致的 NameError）
        on_delete=models.CASCADE,   # 级联删除策略：图书删除时，关联人物也删除
        related_name='characters',      # str: 自定义反向查询名，book.characters.all() 查询人物
        verbose_name='所属图书',
    )

    is_delete = models.BooleanField(default=False, verbose_name='删除标记')  # bool: 软删除

    def __str__(self):
        return self.hname  # str: 返回人物姓名

    # ----------------------------------------------------------------
    # 在 Admin list_display 中显示"计算列"的模型方法
    # ----------------------------------------------------------------
    def gender_label(self):
        """将 bool 型性别字段转为可读文字，用于 Admin 列表页显示"""
        return '男' if self.hgender else '女'  # str: '男' 或 '女'

    # short_description : 设置该方法在 Admin 列表页表头显示的列名
    gender_label.short_description = '性别'

    # admin_order_field : 设置点击该列标题时按哪个真实字段排序
    gender_label.admin_order_field = 'hgender'
```

### 4.2 数据库迁移（Migrate）

迁移是 Django 将模型类同步到数据库表的机制，分为两步：

```bash
# ============================================================
# 步骤一：生成迁移文件
# 作用：扫描 models.py 的变化，生成 migrations/ 目录下的迁移脚本
# 迁移文件记录了"如何从当前状态变为新状态"的操作指令
# ============================================================
python manage.py makemigrations
# 也可以指定某个应用：
python manage.py makemigrations booktest

# ============================================================
# 步骤二：执行迁移
# 作用：读取迁移文件，在数据库中执行 CREATE TABLE / ALTER TABLE 等 SQL
# Django 通过 django_migrations 表记录已执行的迁移，避免重复执行
# ============================================================
python manage.py migrate

# ============================================================
# 查看迁移状态
# [X] 表示已执行，[ ] 表示未执行
# ============================================================
python manage.py showmigrations

# ============================================================
# 进入 Django Shell（带 Django 环境的交互式 Python 终端）
# 可在 shell 中直接操作模型类（用于测试和调试）
# ============================================================
python manage.py shell
```

默认生成的表名规则：`<应用名小写>_<模型类名小写>`
例：`booktest` 应用的 `BookInfo` 类 → 表名为 `booktest_bookinfo`

> **迁移三条重要结论（来自实际开发经验）**
>
> 1. **新增字段前必须有默认值**：若为已有表新增字段且未设置 `default`，`makemigrations` 会报错，
>    需要在命令行交互中临时提供默认值，或在字段上设置 `default=...` 再迁移。
>
> 2. **新增字段不影响已有数据**：`migrate` 执行 `ALTER TABLE ... ADD COLUMN` 时，
>    已有行的该列自动填充字段的 `default` 值；原有字段和数据**不受影响**。
>
> 3. **切换数据库只需 `migrate`**：若 `settings.py` 中只切换了数据库种类（如 SQLite→MySQL），
>    且 `models.py` 未改变，则无需重新 `makemigrations`，**直接 `migrate`** 即可在新数据库建表。

### 6.1 基础查询函数

### 6.2 条件查询详解

```python
# ============================================================
# filter() 的条件查询语法：字段名__条件名=值
# ============================================================
from booktest.models import BookInfo
from datetime import date

# a) 判等（exact，默认条件，可省略）
BookInfo.objects.get(id__exact=1)   # 等价于 BookInfo.objects.get(id=1)

# b) 模糊查询
BookInfo.objects.filter(btitle__contains='传')       # 包含"传"的书名
BookInfo.objects.filter(btitle__startswith='天')     # 以"天"开头的书名
BookInfo.objects.filter(btitle__endswith='部')       # 以"部"结尾的书名
BookInfo.objects.filter(btitle__icontains='哈利')    # 包含"哈利"（不区分大小写）

# c) 空查询（isnull）
BookInfo.objects.filter(btitle__isnull=False)        # 书名不为 NULL 的记录

# d) 范围查询（in）
BookInfo.objects.filter(id__in=[1, 3, 5])            # id 在列表 [1,3,5] 中的记录

# e) 比较查询
# gt: greater than（大于）  gte: greater than or equal（大于等于）
# lt: less than（小于）     lte: less than or equal（小于等于）
BookInfo.objects.filter(id__gt=3)                    # id > 3
BookInfo.objects.filter(bread__gte=20)               # 阅读量 >= 20
BookInfo.objects.filter(bread__lt=50)                # 阅读量 < 50

# f) 日期查询
# __ 后跟的统一都是"查询条件"，日期分量条件属于其中一类特殊条件（Date Transforms）：
# 先从 DateField/DateTimeField 中提取指定时间分量，再对该分量做精确匹配（默认 __exact）。
# 常用日期分量条件：
#   __year     → 年份        __month    → 月份（1–12）   __day      → 日（1–31）
#   __week_day → 星期几       __hour     → 小时           __minute   → 分钟
# 例：bpub_date__year=1980 等价于 bpub_date__year__exact=1980，对应 SQL: WHERE YEAR(bpub_date)=1980
BookInfo.objects.filter(bpub_date__year=1980)             # 提取年份分量，筛选 1980 年出版的图书
BookInfo.objects.filter(bpub_date__month=7)               # 提取月份分量，筛选 7 月出版的图书
BookInfo.objects.filter(bpub_date__gt=date(1980, 1, 1))   # 直接对整个日期值做比较（大于），非分量提取
```

### 6.3 F 对象（字段间比较）

```python
# ============================================================
# F 对象 — 用于模型类属性（字段）之间的比较
# 解决"在 Python 层无法直接比较两个数据库字段"的问题
# ============================================================
from django.db.models import F  # 导入 F 对象

# 查询阅读量大于评论量的图书
# F('bcomment') 代表数据库中 bcomment 列的值，实现字段间比较
BookInfo.objects.filter(bread__gt=F('bcomment'))     # bread > bcomment 的图书

# 查询阅读量大于 2 倍评论量的图书
# F 对象支持算术运算（+、-、*、/）
BookInfo.objects.filter(bread__gt=F('bcomment') * 2) # bread > bcomment*2 的图书
```

### 6.4 Q 对象（逻辑组合查询）

```python
# ============================================================
# Q 对象 — 用于条件之间的逻辑运算（AND / OR / NOT）
# filter() 多条件默认是 AND，OR / NOT 必须使用 Q 对象
# ============================================================
from django.db.models import Q  # 导入 Q 对象

# AND 关系（两种写法等价）
BookInfo.objects.filter(id__gt=2, bread__gt=30)            # 普通多条件（隐式 AND）
BookInfo.objects.filter(Q(id__gt=2) & Q(bread__gt=30))     # Q 对象显式 AND

# OR 关系（必须使用 Q 对象，| 运算符）
BookInfo.objects.filter(Q(id__gt=3) | Q(bread__gt=30))     # id>3 OR 阅读量>30

# NOT 关系（~ 运算符，取反）
BookInfo.objects.filter(~Q(id=3))                          # id 不等于 3
```

### 6.5 聚合函数

```python
# ============================================================
# 聚合函数 — 对查询结果集进行统计计算
# aggregate() 返回 dict；count() 直接返回 int
# ============================================================
from django.db.models import Sum, Count, Max, Min, Avg  # 导入聚合函数类

# aggregate() — 返回值为 dict，键名格式为 "字段名__聚合函数名小写"
result = BookInfo.objects.all().aggregate(Count('id'))  # dict: {'id__count': 5}
result2 = BookInfo.objects.aggregate(Sum('bread'))       # dict: {'bread__sum': 126}
result3 = BookInfo.objects.aggregate(Avg('bread'))       # dict: {'bread__avg': 25.2}
result4 = BookInfo.objects.aggregate(Max('bread'))       # dict: {'bread__max': 58}
result5 = BookInfo.objects.aggregate(Min('bread'))       # dict: {'bread__min': 12}

# count() — 直接返回 int，统计满足条件的记录数
total = BookInfo.objects.all().count()                   # int: 所有图书数量
total2 = BookInfo.objects.count()                        # int: 等价写法（all() 可省略）
filtered_count = BookInfo.objects.filter(id__gt=3).count()  # int: id>3 的图书数量
```

### 6.6 QuerySet 特性

```python
# ============================================================
# QuerySet（查询集）核心特性
# ============================================================

# 特性一：惰性查询（Lazy Evaluation）
# QuerySet 对象创建时不立即访问数据库，只有在以下情况才执行 SQL：
# 1. 迭代（for 循环）  2. 切片  3. 转换为列表  4. 调用 len() / count()  5. 调用 bool()
books = BookInfo.objects.all()   # QuerySet: 此时未访问数据库（SQL 未执行）
for b in books:                  # 迭代时才真正执行 SELECT SQL
    print(b.btitle)

# 特性二：缓存（Caching）
# 同一个 QuerySet 对象第一次使用时执行 SQL 并缓存结果
# 之后再使用该 QuerySet 直接读缓存，不再发起数据库请求
books = BookInfo.objects.all()   # QuerySet（未缓存）
list(books)                      # 执行 SQL，结果缓存到 QuerySet 内部
list(books)                      # 直接读缓存，不再访问数据库

# 切片操作 — 对 QuerySet 切片产生新 QuerySet（不允许负数下标）
b3 = books[0:3]                  # QuerySet: 前 3 条记录（对应 SQL LIMIT 3）

# exists() — 判断查询集是否有数据，返回 bool
has_data = BookInfo.objects.filter(id__gt=10).exists()  # bool: 是否存在 id>10 的图书
```

## 七、模型关联（一对多 / 多对多 / 一对一 / 自关联）

> **`__` 的两种语义**
>
> | 位置 | 作用 | 示例 |
> | ---- | ---- | ---- |
> | 字段名之前 | 跨表遍历——沿关联关系跳到另一张表的字段，Django 底层翻译为 JOIN，一次查询完成，不产生额外请求 | `characters__hcomment` |
> | 字段名之后 | 查询条件——对字段值做比较或匹配 | `__contains`、`__gt` |
>
> 两者可以链式组合：`characters__hcomment__contains='咒'` = 跨到 characters 表 → 取 hcomment 字段 → 应用 contains 条件。
>
> `characters` 来自外键的 `related_name='characters'`；若未设置，默认反向名为 `characterinfo_set`。

### 7.1 一对多关系

```python
# ============================================================
# 一对多关系：ForeignKey 定义在"多"的一端
# 示例：一本图书对应多个人物（一对多）
# ============================================================

# 正向查询（多 → 一）：通过 ForeignKey 属性直接访问关联对象
h = CharacterInfo.objects.get(id=1)  # CharacterInfo: 查询一个英雄对象
book = h.hbook                  # BookInfo: 通过外键属性直接得到关联的图书对象
print(book.btitle)              # str: 访问图书名称

# 反向查询（一 → 多）：通过 related_name（或默认的 <多类名小写>_set）查询
b = BookInfo.objects.get(id=1)             # BookInfo: 查询一本图书
characters = b.characters.all()                    # QuerySet[CharacterInfo]: 通过 related_name='characters' 查询关联人物
# 若未设置 related_name，默认为：b.characterinfo_set.all()

# 通过模型类实现跨关联查询（双下划线跨表）
# 通过多类的条件查询一类的数据（跨表到一类）
BookInfo.objects.filter(characters__hcomment__contains='咒')  # 人物描述含"八"的图书
BookInfo.objects.filter(characters__id__gt=3)                 # 关联人物 id>3 的图书

# 通过一类的条件查询多类的数据（跨表到多类）
CharacterInfo.objects.filter(hbook__btitle__contains='魔法')   # 属于书名含"八部"的图书的人物
```

```python
# ============================================================
# 外键关联操作示例
# ============================================================

# 创建图书
```

### 7.2 多对多关系

```python
# ============================================================
# 多对多关系：ManyToManyField 只需在任意一端定义一次，不能两端同时定义
# 若两端都写，Django 会创建两张中间表，导致数据冗余和查询混乱
# Django 自动创建中间表存储关联关系
# 示例：新闻类型（NewsType）↔ 新闻（NewsInfo）多对多
# ============================================================
from django.db import models


class NewsType(models.Model):
    """新闻类型模型类"""
    type_name = models.CharField(max_length=20, verbose_name='类型名称')  # str: 类型名

    # ManyToManyField — 多对多关系，定义在任意一端均可
    # Django 自动创建名为 booktest_newstype_type_news 的中间关联表
    # 注意：ManyToManyField 不支持 on_delete 参数——它不在模型表上添加外键列，
    # 而是通过中间表管理关联，任意一方记录被删除时中间表对应行自动清除
    type_news = models.ManyToManyField(
        'NewsInfo',                  # str: 关联的模型类名
        related_name='news_types',   # str: 反向查询名，news_obj.news_types.all() 查询所属类型
        verbose_name='关联新闻',
    )

    def __str__(self):
        return self.type_name


class NewsInfo(models.Model):
    """新闻信息模型类"""
    title = models.CharField(max_length=128, verbose_name='标题')         # str: 标题
    pub_date = models.DateTimeField(auto_now_add=True, verbose_name='发布时间')  # datetime: 自动设置创建时间
    content = models.TextField(verbose_name='内容')                        # str: 新闻内容

    def __str__(self):
        return self.title
```

```python
# ============================================================
# 多对多关联操作（在 shell 中演示）
# ============================================================
from booktest.models import NewsType, NewsInfo

news_type = NewsType.objects.get(id=1)   # NewsType: 体育新闻类型
all_news = NewsInfo.objects.all()         # QuerySet[NewsInfo]: 所有新闻

# add() — 建立多对多关联（可传对象或 id）
news_type.type_news.add(1, 2)            # 将 id=1 和 id=2 的新闻关联到该类型

# set() — 设置多对多关联（覆盖原有关联）
news_type.type_news.set(all_news)        # 将所有新闻关联到该类型（覆盖原有关联）

# remove() — 移除多对多关联
news_type.type_news.remove(1, 2)         # 移除 id=1 和 id=2 的新闻与该类型的关联
```

### 7.3 一对一关系

```python
# ============================================================
# 一对一关系：OneToOneField，只需在一端定义，不能两端同时定义
# 若两端都写，Django 会在两张表上各建一个外键，形成循环依赖，迁移将报错
# 通常定义在"扩展"那端（持有额外信息的表），保持主表干净
# 示例：员工基本信息（EmployeeBasicInfo）↔ 员工详细信息（EmployeeDetailInfo）
# ============================================================
from django.db import models


class EmployeeBasicInfo(models.Model):
    """员工基本信息"""
    name = models.CharField(max_length=20, verbose_name='姓名')   # str: 姓名
    gender = models.BooleanField(default=False, verbose_name='性别')  # bool: 性别
    age = models.IntegerField(verbose_name='年龄')                  # int: 年龄

    def __str__(self):
        return self.name


class EmployeeDetailInfo(models.Model):
    """员工详细信息（一对一扩展员工基本信息）"""
    addr = models.CharField(max_length=256, verbose_name='联系地址')  # str: 地址

    # OneToOneField — 一对一关系，语法与 ForeignKey 相同
    # 一对一关系相当于 ForeignKey + unique=True
    employee_basic = models.OneToOneField(
        'EmployeeBasicInfo',         # str: 关联的模型类名
        on_delete=models.CASCADE,    # 基本信息删除时，详细信息也删除
        related_name='detail',       # str: 反向查询名（basic.detail 访问详细信息）
        verbose_name='关联员工',
    )

    def __str__(self):
        return self.employee_basic.name
```

### 7.4 自关联

```python
# ============================================================
# 自关联 — 特殊的一对多关系，关联的是同一张表的记录
# 典型场景：地区（省→市→县）、分类（父分类→子分类）、评论（父评论→子评论）
# ============================================================
from django.db import models


class AreaInfo(models.Model):
    """地区模型类（自关联实现省市县树形结构）"""
    atitle = models.CharField(max_length=20, verbose_name='地区名称')  # str: 地区名称

    # 'self' 表示关联自身这张表（即外键指向同一模型类）
    # null=True, blank=True 表示顶级地区（省级）没有父级，外键可为 NULL
    a_parent = models.ForeignKey(
        'self',                          # str: 'self' 表示自关联
        on_delete=models.CASCADE,        # 父级删除时，子级也删除
        null=True,                       # bool: 允许 NULL（顶级地区无父级）
        blank=True,                      # bool: Admin 表单允许为空
        related_name='children',         # str: 反向查询名，area.children.all() 查子级
        verbose_name='父级地区',
    )

    def __str__(self):
        return self.atitle
```

```python
# ============================================================
# 自关联查询示例（在视图函数中）
# ============================================================
def areas_view(request):
    """获取广州市的上级地区和下级地区"""
    area = AreaInfo.objects.get(atitle='广州市')  # AreaInfo: 广州市对象
    parent = area.a_parent                         # AreaInfo | None: 父级地区（广东省）
    children = area.children.all()                 # QuerySet[AreaInfo]: 所有子级地区（区/县）
    return render(request, 'areas.html', {
        'area': area,          # AreaInfo: 当前地区
        'parent': parent,      # AreaInfo: 父级地区
        'children': children,  # QuerySet: 子级地区列表
    })
```

### 7.5 自定义管理器类

```python
# ============================================================
# booktest/models.py — 自定义管理器类
# 使用场景：
#   1. 改变默认查询结果集（如只返回未删除的记录）
#   2. 添加额外的数据库操作方法（封装常用操作）
# ============================================================
from django.db import models


class BookInfoManager(models.Manager):
    """图书自定义管理器类，继承自 models.Manager"""

    def all(self):
        """重写 all() 方法，只返回未删除的图书"""
        books = super().all()                    # QuerySet: 调用父类 all()，获取所有记录
        books = books.filter(is_delete=False)    # QuerySet: 过滤出未软删除的记录
        return books                             # QuerySet[BookInfo]: 返回过滤后的查询集

    def create_book(self, btitle, bpub_date):
        """封装创建图书的方法，返回新创建的图书对象"""
        model_class = self.model          # type: 获取管理器绑定的模型类（BookInfo）
        book = model_class()              # BookInfo: 创建模型类空对象
        book.btitle = btitle              # str: 赋值图书名称
        book.bpub_date = bpub_date        # date: 赋值发布日期
        book.save()                       # 保存到数据库
        return book                       # BookInfo: 返回新创建的对象


class BookInfo(models.Model):
    """图书模型类（使用自定义管理器）"""
    btitle = models.CharField(max_length=20)
    bpub_date = models.DateField()
    is_delete = models.BooleanField(default=False)
```

### 9.1 视图函数基础

```python
# ============================================================
# booktest/views.py — 定义视图函数
# 视图函数：接收 HttpRequest → 处理业务逻辑 → 返回 HttpResponse
# ============================================================
from django.http import HttpResponse, JsonResponse, HttpResponseRedirect
from django.shortcuts import render, redirect  # render: 渲染模板; redirect: 重定向
from booktest.models import BookInfo, CharacterInfo


def index(request):
    """首页视图函数 — 返回最简单的文本响应"""
    # request: HttpRequest — Django 自动创建，包含请求的所有信息
    # 视图函数必须有且只有 request 作为第一个参数
    return HttpResponse('Hello Django!')  # HttpResponse: 返回纯文本响应


def show_books(request):
    """图书列表视图 — 查询数据库并渲染模板（使用快捷函数 render）"""
    books = BookInfo.objects.all()  # QuerySet[BookInfo]: 查询所有图书
    # render(request, template_name, context) -> HttpResponse
    #   request      : HttpRequest — 当前请求对象
    #   template_name: str — 模板文件路径（相对于 templates 目录）
    #   context      : dict — 传递给模板的变量字典
    return render(request, 'booktest/show_books.html', {'books': books})


def show_books_manual(request):
    """手动加载模板（等价于 render，用于理解底层流程）"""
    from django.template import loader     # loader: 模板加载器

    books = BookInfo.objects.all()         # QuerySet[BookInfo]: 所有图书

    # 步骤一：loader.get_template(path) -> Template
    #   加载并编译模板文件，返回 Template 对象
    template = loader.get_template('booktest/show_books.html')

    # 步骤二：template.render(context, request) -> str
    #   使用 context 字典渲染模板，得到最终的 HTML 字符串
    html_str = template.render({'books': books}, request)  # str: 渲染后的 HTML 文本

    # 步骤三：将 HTML 字符串包装进 HttpResponse 返回给浏览器
    return HttpResponse(html_str)
    # 以上三步等价于：return render(request, 'booktest/show_books.html', {'books': books})


def detail(request, bid):
    """图书详情视图 — 接收 URL 参数 bid，查询对应图书及其英雄"""
    # bid: int — 来自 URL 路径转换器 <int:bid>，Django 自动传入
    book = BookInfo.objects.get(id=bid)         # BookInfo: 查询指定 id 的图书
    characters = book.characters.all()                  # QuerySet[CharacterInfo]: 查询关联人物
    return render(request, 'booktest/detail.html', {
        'book': book,       # BookInfo: 传给模板的图书对象
        'characters': characters,   # QuerySet: 传给模板的人物列表
    })
```

```python
    path('books/<int:bid>/', views.detail, name='detail'),  # /books/1/ → detail(bid=1)
```

### 9.3 HttpRequest 对象属性

| 属性           | 类型          | 说明                                                      |
| ------------ | ----------- | ------------------------------------------------------- |
| `path`       | `str`       | 请求的 URL 路径（不含域名和查询参数），如 `/books/`                      |
| `method`     | `str`       | 请求方法，如 `'GET'`、`'POST'`                                 |
| `encoding`   | `str`       | 提交数据的编码，通常为 `utf-8`                                     |
| `GET`        | `QueryDict` | GET 请求参数（URL 中 `?key=value` 格式），类似字典                    |
| `POST`       | `QueryDict` | POST 请求体中的表单参数，类似字典                                     |
| `FILES`      | `dict`      | 上传的文件对象，键为表单中的 `name` 属性值                               |
| `COOKIES`    | `dict`      | 请求携带的所有 Cookie，键值均为字符串                                  |
| `session`    | `dict-like` | 当前会话数据（需启用 Session 中间件）                                 |
| `META`       | `dict`      | HTTP 元数据，如 `REMOTE_ADDR`（客户端 IP）、`HTTP_HOST` 等           |

```python
def my_view(request):
```

```python
# views.py
from django.http import Http404                  # Django 内置 HTTP 404 异常
from django.shortcuts import get_object_or_404  # 找不到对象时自动引发 Http404


def book_detail_v1(request, book_id):
    """方式一：手动 try/except 捕获 DoesNotExist，主动抛出 Http404"""
    try:
        book = BookInfo.objects.get(pk=book_id)  # BookInfo: 查询指定图书；找不到抛 DoesNotExist
    except BookInfo.DoesNotExist:
        raise Http404('图书不存在')              # 引发 Http404，Django 自动渲染 404.html
    return HttpResponse(book.btitle)             # str: 图书存在时返回书名


def book_detail_v2(request, book_id):
    """方式二（推荐）：get_object_or_404() 等价于上方 try/except，代码更简洁"""
    # get_object_or_404(Model, **kwargs) -> Model 实例（找不到则引发 Http404）
    book = get_object_or_404(BookInfo, pk=book_id)  # BookInfo: 找不到自动返回 404
    return HttpResponse(book.btitle)                # str: 返回图书名称
```

```python
# views.py
import random                                    # 随机数模块，生成验证码字符
import string                                    # 字符串常量模块，提供字母数字集合
from io import BytesIO                           # 内存字节流，避免写临时文件

from PIL import Image, ImageDraw, ImageFont      # Pillow：图像 / 画布 / 字体操作类
from django.http import HttpResponse             # 返回 HTTP 响应


def captcha(request):
    """
    生成图片验证码并将文字存入 Session。
    返回值：HttpResponse，Content-Type 为 image/png，客户端浏览器直接显示为图片。
    """
    # ----------------------------------------------------------------
    # 1. 生成随机 4 位验证码字符串（大写字母 + 数字）
    # ----------------------------------------------------------------
    chars = string.ascii_uppercase + string.digits          # 'ABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789'
    code = ''.join(random.choices(chars, k=4))              # 随机抽取 4 个字符拼成验证码文本

    # ----------------------------------------------------------------
    # 2. 创建图片画布（宽120像素 × 高40像素，RGB 模式，白色背景）
    # ----------------------------------------------------------------
    width, height = 120, 40                                  # 图片尺寸（像素）
    bg_color = (255, 255, 255)                               # 背景颜色：白色 RGB 元组
    img = Image.new('RGB', (width, height), bg_color)        # 创建 PIL Image 对象
    draw = ImageDraw.Draw(img)                               # 创建画布，用于在图片上绘制文字/线条

    # ----------------------------------------------------------------
    # 3. 绘制干扰线（随机颜色、随机位置）
    # ----------------------------------------------------------------
    for _ in range(5):                                       # 绘制 5 条干扰线
        x1 = random.randint(0, width)                        # 线段起点 x 坐标（0~120 随机）
        y1 = random.randint(0, height)                       # 线段起点 y 坐标（0~40 随机）
        x2 = random.randint(0, width)                        # 线段终点 x 坐标
        y2 = random.randint(0, height)                       # 线段终点 y 坐标
        line_color = (                                       # 干扰线颜色：随机深色
            random.randint(0, 150),                          # R 通道（0~150）
            random.randint(0, 150),                          # G 通道（0~150）
            random.randint(0, 150),                          # B 通道（0~150）
        )
        draw.line([(x1, y1), (x2, y2)], fill=line_color, width=1)  # 画线

    # ----------------------------------------------------------------
    # 4. 将验证码文字逐字符绘制到图片（每个字符随机偏移，增加识别难度）
    # ----------------------------------------------------------------
    try:
        # 优先使用系统等宽字体（Windows）
        font = ImageFont.truetype('C:/Windows/Fonts/cour.ttf', size=28)  # 字体大小 28pt
    except IOError:
        font = ImageFont.load_default()                      # 回退到 Pillow 内置默认字体

    for i, char in enumerate(code):                          # 遍历 4 个字符，i 是索引
        char_x = 10 + i * 28 + random.randint(-3, 3)        # 字符 x 起始位置（含随机偏移）
        char_y = random.randint(3, 10)                       # 字符 y 偏移（随机上下浮动）
        char_color = (                                       # 字符颜色：随机深色
            random.randint(50, 200),
            random.randint(50, 200),
            random.randint(50, 200),
        )
        draw.text((char_x, char_y), char, font=font, fill=char_color)  # 在坐标处写入字符

    # ----------------------------------------------------------------
    # 5. 将验证码文字（小写，统一比较）存入 Session，过期 5 分钟
    # ----------------------------------------------------------------
    request.session['captcha_code'] = code.lower()           # 存入 session，供后续视图比对
    request.session.set_expiry(300)                          # 验证码 5 分钟内有效

    # ----------------------------------------------------------------
    # 6. 将图片输出为 PNG 格式的字节流并返回给浏览器
    # ----------------------------------------------------------------
    buffer = BytesIO()                                       # 创建内存字节流对象
    img.save(buffer, format='PNG')                           # 将 PIL 图片保存到内存中
    buffer.seek(0)                                           # 将读取指针回到流的起始位置

    # HttpResponse：第一参数为响应体（bytes），content_type 告知浏览器这是图片
    return HttpResponse(buffer.getvalue(), content_type='image/png')
```

```python
# views.py
def register(request):
    """处理注册表单，校验验证码"""
    if request.method == 'POST':
        username = request.POST.get('username', '').strip()       # 获取用户名
        password = request.POST.get('password', '').strip()       # 获取密码
        captcha_input = request.POST.get('captcha', '').lower()   # 用户输入验证码（转小写）

        # 从 Session 取出服务器端存储的验证码（已存为小写）
        captcha_code = request.session.get('captcha_code', '')    # 取不到则为空串

        if captcha_input != captcha_code:                         # 比对验证码
            return HttpResponse('验证码错误，请重新输入')
        if not username or not password:
            return HttpResponse('用户名和密码不能为空')

        # 验证通过，执行注册逻辑...
        del request.session['captcha_code']                       # 验证成功后删除 session 中的验证码，防止重复使用
        return HttpResponse('注册成功')

    # GET 请求：渲染注册页
    return render(request, 'register.html')
```

## 十、模板（DTL / 变量 / 标签 / 过滤器 / 继承）

DTL（Django Template Language）是 Django 内置的模板语言，包含四种语法元素：变量、标签、过滤器、注释。

### 10.1 配置模板目录

```python
# ============================================================
# settings.py — 配置模板目录
# ============================================================

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],  # list: 模板搜索目录（优先于应用内 templates）
        'APP_DIRS': True,  # bool: True 时自动在每个已注册应用的 templates 目录中搜索模板
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.debug',
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]
# 模板加载顺序：
# 1. DIRS 列表中的目录（从前到后）—— 即项目根目录下的 templates/
# 2. 每个已注册应用的 templates 子目录（按 INSTALLED_APPS 顺序）
# 若 DIRS 和各应用 templates 均未找到模板文件，Django 抛出 TemplateDoesNotExist
```

> **模板查找顺序详解**
>
> ```
> render(request, 'booktest/show_books.html', {...})
> ```
>
> Django 按以下顺序搜索 `booktest/show_books.html`：
>
> 1. `<BASE_DIR>/templates/booktest/show_books.html`（`DIRS` 配置的项目级目录，**优先**）
> 2. `<已注册应用目录>/templates/booktest/show_books.html`（各应用的 `templates` 子目录，**次之**）
> 3. 都找不到 → 抛出 `TemplateDoesNotExist` 异常
>
> **最佳实践**：在应用的 `templates/` 下再建与应用同名的子目录（如 `booktest/show_books.html`），
> 避免不同应用的同名模板文件互相覆盖。

```python
# ============================================================
# booktest/templatetags/filters.py — 自定义过滤器
# 必须：在应用目录下创建 templatetags 文件夹（名称固定）
# 必须：在 templatetags 下创建 __init__.py 文件
# ============================================================
from django.template import Library  # 导入 Library 类

register = Library()  # Library 实例：注册自定义过滤器和标签的容器


@register.filter
def mod(num):
    """
    判断 num 是否为偶数（一个参数的过滤器）
    用法：{{ book.id|mod }}
    返回值: bool — True 表示偶数，False 表示奇数
    """
    return num % 2 == 0  # bool: 是否能被 2 整除


@register.filter
def mod_val(num, val):
    """
    判断 num 是否能被 val 整除（两个参数的过滤器）
    用法：{{ book.id|mod_val:3 }}
    参数:
        num: int — 模板变量（过滤器第一个参数）
        val: int — 冒号后的参数（过滤器第二个参数）
    返回值: bool — True 表示能整除
    """
    return num % val == 0  # bool: 是否能被 val 整除
```

```python
# ============================================================
# models.py — 图片上传模型
# ============================================================
from django.db import models


class PicTest(models.Model):
    """图片测试模型类"""
    # ImageField — 图片字段，数据库中存储图片路径字符串
    # upload_to : str — 上传文件在 MEDIA_ROOT 下的子目录路径
    # 需要安装 Pillow 包（pip install Pillow）

        upload_to='booktest',   # str: 图片保存到 MEDIA_ROOT/booktest/ 目录

```

```python
# ============================================================
# views.py — 用户自定义上传图片视图
# ============================================================
import os
import time
import random
from django.conf import settings  # 导入项目配置（访问 MEDIA_ROOT）
from django.http import HttpResponse
from booktest.models import PicTest


def upload_handle(request):
    """处理图片上传请求"""
    # request.FILES['pic'] — 获取上传文件的处理对象
    # 文件小于 2.5MB 时为 InMemoryUploadedFile（内存存储）
    # 文件大于 2.5MB 时为 TemporaryUploadedFile（临时文件存储）
    pic = request.FILES['pic']  # UploadedFile: 上传文件对象

    # 生成唯一文件名，避免同名文件覆盖
    time_str = time.strftime('%Y%m%d%H%M%S')  # str: 时间戳字符串
    rand_num = random.randint(100000, 999999)  # int: 6位随机数
    unique_name = f'{time_str}{rand_num}{os.path.splitext(pic.name)[1]}'  # str: 唯一文件名

    # 构建保存路径
    save_path = os.path.join(settings.MEDIA_ROOT, 'booktest', unique_name)  # str: 绝对路径

    # 分块写入文件（pic.chunks() 逐块读取，适合大文件）
    with open(save_path, 'wb') as f:
        for chunk in pic.chunks():          # bytes: 每次读取一块数据
            f.write(chunk)                  # 写入到本地文件

    # 在数据库中记录上传路径（存相对路径，相对于 MEDIA_ROOT）
    PicTest.objects.create(goods_pic=f'booktest/{unique_name}')  # 创建数据库记录

    return HttpResponse('上传成功')
```

## 十二、状态保持（Cookie / Session）

HTTP 协议是**无状态**的，每次请求相互独立。Cookie 和 Session 用于在多次请求间保持用户状态。

### 12.1 Cookie

```python
# ============================================================
# Cookie — 存储在浏览器端的键值对，随请求自动携带
# 特点：
#   1. 以键值对形式存储，键值均为字符串
#   2. 基于域名安全（不同域名的 Cookie 相互隔离）
#   3. 有过期时间（不指定则浏览器关闭后自动清除）
# ============================================================
from django.http import HttpResponse
from datetime import datetime, timedelta


def set_cookie(request):
    """设置 Cookie"""
    response = HttpResponse('设置 Cookie 成功')         # 创建响应对象

    # response.set_cookie(key, value, max_age=None, expires=None)
    #   key     : str — Cookie 名称
    #   value   : str — Cookie 值
    #   max_age : int — 过期时长（秒），不设置则浏览器关闭时过期
    #   expires : datetime — 精确过期时间点（与 max_age 二选一）
    response.set_cookie('username', 'admin')                    # 浏览器关闭后过期
    response.set_cookie('num', 2, max_age=14 * 24 * 3600)      # 14 天后过期
    response.set_cookie(
        'token', 'abc123',
        expires=datetime.now() + timedelta(days=7),             # 7 天后的具体时间点过期
    )
    return response


def get_cookie(request):
    """读取 Cookie"""
    # request.COOKIES 是标准字典，键值均为字符串
    # 直接取值（键不存在时抛 KeyError）
    if 'username' in request.COOKIES:
        username = request.COOKIES['username']  # str: Cookie 中 username 的值
    else:
        username = ''                           # str: Cookie 不存在时使用空字符串

    # .get() 取值（键不存在时返回默认值，更安全）
    num = request.COOKIES.get('num', '0')       # str: 默认值为 '0'
    return HttpResponse(f'username={username}, num={num}')


def delete_cookie(request):
    """删除 Cookie"""
    response = HttpResponse('删除 Cookie 成功')
    response.delete_cookie('username')  # 删除指定名称的 Cookie
    return response
```

### 12.3 Cookie 与 Session 对比

| 对比项    | Cookie                | Session                       |
| ------ | --------------------- | ----------------------------- |
| 存储位置   | **浏览器端**（由浏览器创建）      | **服务器端**（由服务器创建，默认存于数据库表）     |
| 存储内容   | 只能是字符串                | 任意 Python 类型                  |
| 安全性    | 低（用户可查看和篡改）           | 高（用户只持有 sessionid）            |
| 容量     | 单 Cookie 约 4KB        | 无明显限制                         |
| 作用范围   | **默认同一域名下所有路径**共享     | 按 **浏览器 + IP + 域名**区分会话       |
| 依赖关系   | 独立                    | 依赖 Cookie（浏览器收到响应后 sessionid 存于 Cookie） |
| 过期行为   | 未设置过期时间→浏览器关闭即清空；设置后持久 | 可通过 `set_expiry()` 控制         |
| 典型应用   | **记住用户名**（自动填充表单）     | **自动登录**（保持登录状态、购物车）          |

> **Cookie 作用范围说明**：
> - 默认情况下，设置 Cookie 时未指定 `path`，则同一域名下**所有路径**的请求都会携带该 Cookie
> - 指定 `path='/admin/'` 时，只有 `/admin/` 及其子路径的请求才携带该 Cookie
> - 浏览器标签页的 Headers 面板中可以看到当前页面携带的所有 Cookie
>
> **Session 会话区分说明**：
> - Django 通过 sessionid（存于 Cookie）区分不同会话
> - 不同浏览器、不同 IP 或不同域名，即使是同一用户也会得到不同的 session 记录
> - 服务器端的 session 数据存于 `django_session` 表（默认），字段包括 `session_key`、`session_data`、`expire_date`

**自动登录实现思路（Session 典型应用）**：

```python
# views.py — 登录时将状态写入 Session，后续请求自动识别
from django.shortcuts import render, redirect  # render: 渲染模板; redirect: 重定向
from django.http import HttpResponse           # HttpResponse: 返回文本响应


def login(request):
    """登录视图：校验成功后将用户信息写入 session，实现自动登录"""
    if request.method == 'POST':
        username = request.POST.get('username')  # str: 用户名
        password = request.POST.get('password')  # str: 密码
        # 此处省略数据库校验...
        if username == 'admin' and password == '123':
            request.session['is_login'] = True        # bool: 标记已登录
            request.session['username'] = username    # str: 存储用户名
            request.session.set_expiry(7 * 24 * 3600) # int: 7天内自动登录
            return redirect('index')
    return render(request, 'login.html')


def index(request):
    """首页视图：检查 session 实现自动登录（无需重新输入账号密码）"""
    if 'is_login' not in request.session:    # 未登录 → 重定向到登录页
        return redirect('login')
    username = request.session.get('username', '')  # str: 从 session 获取用户名
    return render(request, 'index.html', {'username': username})
```

## 十三、中间件（Middleware）

中间件是 Django 请求/响应处理管道中的**钩子函数**，可以在请求到达视图前或响应返回前插入自定义处理逻辑。

```
HTTP 请求 → 中间件①.__call__ → 中间件②.__call__ → process_view → 视图函数
HTTP 响应 ← 中间件①响应处理 ← 中间件②响应处理 ← 视图函数返回
```

中间件方法的调用顺序（按注册顺序）：
1. `__init__`：服务器启动时调用一次（初始化）
2. `__call__` 前半段：产生 HttpRequest 对象、URL 匹配前调用
3. `process_view`：URL 匹配后、视图函数调用前调用
4. `__call__` 后半段（`get_response` 之后）：视图函数调用后、响应返回浏览器前调用
5. `process_exception`：视图函数抛出异常时调用（按注册逆序）

### 13.1 定义中间件

```python
# ============================================================
# booktest/middleware.py — 自定义中间件
# ============================================================
from django.http import HttpResponse


# ── IP 黑名单中间件 ──────────────────────────────────────────────────────
class BlockedIPSMiddleware:
    """
    IP 黑名单中间件
    禁止黑名单中的 IP 访问任何页面
    """

    EXCLUDE_IPS = ['192.168.0.108', '192.168.0.109']  # list[str]: IP 黑名单

    def __init__(self, get_response):
        """
        Django 应用启动时调用一次（只初始化一次，非每次请求都调用）
        get_response: callable — 调用后触发下一个中间件的 __call__ 或视图函数
        """
        self.get_response = get_response  # callable: 保存下游处理函数（链式调用的下一环）

    def __call__(self, request):
        """
        每次请求时调用（产生 HttpRequest 对象后、URL 匹配前）
        request: HttpRequest — 当前请求对象
        返回值: HttpResponse — 当前响应对象
        """
        # self.get_response(request) 会触发：
        #   1. process_view 的调用
        #   2. 视图函数的执行
        #   3. 返回视图函数的 HttpResponse
        response = self.get_response(request)  # HttpResponse: 视图函数的响应
        # get_response 调用后，视图函数已执行完毕（响应返回浏览器前的处理位置）
        return response  # HttpResponse: 将响应返回给上游中间件或浏览器

    def process_view(self, request, view_func, *view_args, **view_kwargs):
        """
        URL 匹配成功后、视图函数调用前触发
        request  : HttpRequest — 当前请求对象
        view_func: callable — 即将调用的视图函数
        view_args: tuple — 视图函数的位置参数
        view_kwargs: dict — 视图函数的关键字参数
        返回值: None（继续执行）或 HttpResponse（中断执行，直接返回该响应）
        """
        # request.META['REMOTE_ADDR'] — 获取客户端 IP 地址
        user_ip = request.META['REMOTE_ADDR']  # str: 客户端 IP 地址
        if user_ip in BlockedIPSMiddleware.EXCLUDE_IPS:
            return HttpResponse('<h1>403 Forbidden — 您的 IP 已被封禁</h1>', status=403)
        # 返回 None 表示不拦截，继续执行视图函数
        return None


# ── 请求日志中间件 ──────────────────────────────────────────────────────
class RequestLogMiddleware:
    """请求日志中间件，记录每次请求的方法、路径和响应状态码"""

    def __init__(self, get_response):
        print('--- 日志中间件初始化 ---')  # 仅在服务器启动时打印一次
        self.get_response = get_response

    def __call__(self, request):
        print(f'→ 请求: {request.method} {request.path}')  # 请求到来时打印
        response = self.get_response(request)               # 调用视图函数
        print(f'← 响应: {response.status_code}')           # 响应返回时打印
        return response

    def process_exception(self, request, exception):
        """
        视图函数发生异常时调用
        exception: Exception — 异常对象
        返回值: None（继续传播异常）或 HttpResponse（处理异常并返回）
        注意：多个中间件都有 process_exception 时，调用顺序与注册顺序相反
        """
        print(f'!! 视图函数异常: {exception}')
        return None  # 返回 None 表示不处理，让 Django 默认的错误处理接管
```

```python
from django.core.paginator import Paginator  # 导入分页器类
from booktest.models import AreaInfo


def show_area(request, pindex=1):
    """地区分页视图，默认显示第 1 页"""
    # 查询所有省级地区（顶级地区，父级为 NULL）
    areas = AreaInfo.objects.filter(a_parent__isnull=True)  # QuerySet: 所有省级地区

    # Paginator(object_list, per_page) -> Paginator
    #   object_list: QuerySet / list — 要分页的数据集
    #   per_page   : int — 每页显示的记录数
    paginator = Paginator(areas, 10)  # Paginator: 每页 10 条记录

    # paginator.num_pages  : int — 总页数
    # paginator.page_range : range — 页码范围（如 range(1, 6) 表示 1~5 页）
    pindex = int(pindex)                   # int: 确保页码为整数
    page = paginator.page(pindex)          # Page: 第 pindex 页的 Page 对象

    # Page 对象属性：
    # page.number             : int — 当前页页码
    # page.object_list        : QuerySet — 当前页的数据
    # page.paginator          : Paginator — 对应的 Paginator 对象
    # page.has_previous()     : bool — 是否有上一页
    # page.has_next()         : bool — 是否有下一页
    # page.previous_page_number(): int — 上一页页码
    # page.next_page_number()    : int — 下一页页码

    return render(request, 'booktest/show_area.html', {'page': page})
```

```python
        return self.hname  # str: 显示人物姓名

    class Meta:
        db_table = 'characterinfo'
        verbose_name = '人物'
        verbose_name_plural = '英雄列表'
```

### 15.6 视图函数（完整 CRUD）

```python
# ============================================================
# booktest/views.py — 完整视图函数（图书增删查）
# ============================================================
from django.shortcuts import render, redirect
from django.http import HttpResponse, JsonResponse
from django.urls import reverse
from booktest.models import BookInfo, CharacterInfo
from datetime import date


# ── 图书列表 ──────────────────────────────────────────────────────────
def show_books(request):
    """显示所有图书列表"""
    books = BookInfo.objects.filter(is_delete=False).order_by('-bread')
    # QuerySet[BookInfo]: 未删除的图书，按阅读量降序排列
    return render(request, 'booktest/show_books.html', {'books': books})


# ── 图书详情（英雄列表）─────────────────────────────────────────────────
def detail(request, bid):
    """显示指定图书及其人物信息"""
    try:
        book = BookInfo.objects.get(id=bid, is_delete=False)  # BookInfo: 查询图书
    except BookInfo.DoesNotExist:
        return HttpResponse('图书不存在', status=404)
    characters = book.characters.filter(is_delete=False)  # QuerySet[CharacterInfo]: 图书的人物列表
    return render(request, 'booktest/detail.html', {'book': book, 'characters': characters})


# ── 新增图书 ──────────────────────────────────────────────────────────
def add_book(request):
    """新增图书并重定向到列表页"""
    if request.method == 'POST':
        # 从 POST 请求体中获取表单数据
        btitle = request.POST.get('btitle')             # str: 图书名称
        bpub_date_str = request.POST.get('bpub_date')  # str: 发布日期字符串

        # 简单校验（生产环境使用 Django Form 进行完整校验）
        if not btitle:
            return HttpResponse('图书名称不能为空', status=400)

        bpub_date = date.fromisoformat(bpub_date_str)  # date: 字符串转日期对象
        BookInfo.objects.create(btitle=btitle, bpub_date=bpub_date)  # 创建并保存

        return redirect(reverse('booktest:show_books'))  # 重定向到列表页
    else:
        return render(request, 'booktest/add_book.html')  # GET 请求显示表单页


# ── 删除图书 ──────────────────────────────────────────────────────────
def delete_book(request, bid):
    """软删除指定图书（设置 is_delete 标记而非物理删除）"""
    try:
        book = BookInfo.objects.get(id=bid)
        book.is_delete = True   # bool: 软删除标记置为 True
        book.save()             # 更新数据库记录
    except BookInfo.DoesNotExist:
        pass
    return redirect(reverse('booktest:show_books'))  # 重定向回列表页


# ── Ajax 获取图书英雄数据 ─────────────────────────────────────────────
def get_characters_ajax(request, bid):
    """Ajax 接口：返回指定图书的所有英雄（JSON 格式）"""
    characters = CharacterInfo.objects.filter(hbook_id=bid, is_delete=False)  # QuerySet: 人物列表
    characters_data = [
        {'id': h.id, 'name': h.hname, 'comment': h.hcomment}
        for h in characters
    ]  # list[dict]: 英雄数据列表
    return JsonResponse({'characters': characters_data})  # JSON: {'characters': [...]}
```

### 16.1 Django 核心知识点回顾

| 知识点          | 关键 API / 文件                                                  | 说明                   |
| ------------ | ------------------------------------------------------------ | -------------------- |
| 项目创建         | `django-admin startproject` / `startapp`                     | 初始化项目和应用              |
| 模型设计         | `models.Model` / 字段类型 / `makemigrations` / `migrate`        | ORM 映射，自动建表           |
| CRUD 操作      | `objects.create()` / `.get()` / `.filter()` / `.save()` / `.delete()` | 数据库增删改查              |
| 高级查询         | `F()` / `Q()` / `aggregate()` / `order_by()` / QuerySet 特性  | 字段比较、逻辑组合、聚合统计        |
| 模型关联         | `ForeignKey` / `ManyToManyField` / `OneToOneField` / 自关联    | 表间关系建模                |
| Admin 后台     | `admin.site.register()` / `ModelAdmin` / `InlineModelAdmin`  | 自动生成数据管理界面            |
| 视图与路由        | `def view(request)` / `path()` / `include()`                 | 请求处理与 URL 分发          |
| 模板渲染         | `render()` / DTL 标签 / 过滤器 / 模板继承                            | 动态 HTML 生成           |
| 静态与媒体文件      | `STATIC_URL` / `{% static %}` / `MEDIA_ROOT` / `ImageField`  | 静态资源管理与文件上传           |
| Cookie       | `response.set_cookie()` / `request.COOKIES`                  | 浏览器端状态保持              |
| Session      | `request.session['key'] = value`                             | 服务器端状态保持              |
| 中间件          | `class Middleware` / `process_view` / `MIDDLEWARE` 注册        | 请求/响应管道中的全局处理钩子       |
| Ajax 与 JSON  | `JsonResponse` / `request.POST` / jQuery `$.ajax()`          | 前后端异步数据交互             |
| 分页           | `Paginator` / `Page` / `page_range`                          | 大数据量分页展示              |
| 反向解析         | `name=` / `{% url %}` / `reverse()`                          | URL 路径解耦，改 URL 不改代码  |
| CSRF 防护      | `{% csrf_token %}` / `CsrfViewMiddleware`                     | 防跨站请求伪造攻击             |

### 16.2 Django 开发完整流程图

```
需求分析
   ↓
① 创建项目 & 应用（startproject / startapp）
   ↓
② 配置 settings.py（数据库 / 应用注册 / 模板 / 静态文件）
   ↓
③ 设计模型类（models.py）→ makemigrations → migrate
   ↓
④ 注册 Admin（admin.py）→ createsuperuser → 后台录入数据
   ↓
⑤ 定义视图函数（views.py）→ 处理请求、操作数据库、调用模板
   ↓
⑥ 配置 URL 路由（urls.py）→ 绑定 URL 路径与视图函数
   ↓
⑦ 编写模板（templates/*.html）→ DTL 渲染动态内容
   ↓
⑧ 测试验证（runserver）→ 功能测试 / 边界测试
   ↓

```
